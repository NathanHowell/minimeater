# ADR 0001: MCU selection

- Status: accepted (2026-10-11)
- Bead: `minimeat-seq.1.3`
- Constraint: the PCB is assembled by JLCPCB, so every part must be in JLC stock. Volume is about 5 boards.

## Context

The controller needs:
- WiFi for MQTT + Home Assistant discovery and OTLP metrics.
- A single USB-C port that does power, flashing, logs and debug, with no separate programming connector.
- Rust embassy firmware.
- About 20 GPIOs: the probe ADC on SPI, the ambient sensor on I2C, fan PWM and tach, servo PWM and enable, USB-C CC sensing, an LED and a button.
- Matter as a stretch goal.

The control law is a small MPC: about 6 decision variables every 10 s. That is negligible compute for any candidate.

## Decision

**Espressif ESP32-C6-WROOM-1-N8** (JLC C5366877, about 2.5k in stock, $4.22). Specs: 8 MB flash, PCB antenna, RISC-V at 160 MHz, 512 KB SRAM, WiFi 6 (2.4 GHz), BLE 5 and 802.15.4.

| | ESP32-C6-WROOM-1-N8 | ESP32-S3-WROOM-1 | ESP32-C3 | STM32 + WiFi module |
|---|---|---|---|---|
| Native USB Serial/JTAG (flash + log + debug over the one USB-C) | yes | yes (plus USB-OTG) | yes | needs DFU/SWD, or the radio module has a separate path |
| Rust toolchain | stable `riscv32imac`, first-class esp-hal/embassy | Xtensa: needs the `espup` fork toolchain | stable RISC-V | excellent embassy support, but the WiFi stack is the problem |
| Thread / 802.15.4 (Matter-over-Thread option) | yes | no | no | no |
| RAM / flash headroom | 512 KB / 8 MB | 512 KB + PSRAM / up to 16 MB | 400 KB / 4 MB | varies |
| JLC stock | 2.5k (N8) | 34k | not checked | not checked |

- **Native USB:** the USB-Serial-JTAG block on GPIO12/13 lets `espflash` and `probe-rs` flash and auto-reset into download mode over the box's only port. This was the hard requirement.
- **Toolchain:** the C6 is RISC-V, so the project builds on stable Rust with no Xtensa fork. That simplifies CI and the host/target split in the simulation environment (`.4.16`).
- **Matter:** 802.15.4 keeps Matter-over-Thread available. Matter over WiFi works on either part.
- **Why N8 and not N4:** OTA needs two app slots. rs-matter adds hundreds of KB, so 8 MB is what leaves room for two Matter-capable images. The N4 also has less stock at JLC (370).
- **The ESP32-S3 was rejected.** It wins only on PSRAM, GPIO count and ADC channels, none of which we need now that the probes use an external ADC (ADR 0002). Its cost is the Xtensa toolchain.
- **Antenna:** use the PCB-antenna variant, placed at a board edge with the keep-out clear of copper. The box is plastic, but the egg's steel bands and the stainless intake tube are close. Place the antenna away from the tube, on the side facing away from the egg. The WROOM-1U external-antenna variant is not stocked at JLC, so there is no fallback there.

## Pin budget (WROOM-1 exposes about 21 usable GPIO)

| Function | Pins | Notes |
|---|---|---|
| USB D-/D+ | GPIO12, GPIO13 | fixed |
| SPI SCLK/MOSI/MISO | 3 | ADS1220 + MAX31856 (DNP) |
| CS_ADC, DRDY_ADC, CS_TC | 3 | |
| I2C SDA/SCL | 2 | TMP117 |
| Fan PWM (LEDC 25 kHz), fan tach | 2 | the tach needs pull-up and clamp because the fan runs at 5 V |
| Servo PWM, servo power enable | 2 | cutting servo power stops hold current and jitter between moves |
| USB-C CC1/CC2 sense | 2 | must be ADC1 pins (GPIO0-6). Reads the source's advertised current (Default/1.5 A/3 A) |
| Status LED | 1 | not on GPIO8 or GPIO9 (strapping) |
| User button | GPIO9 | doubles as BOOT; safe because it is only read after boot |
| UART0 TX/RX | 2 | debug fallback, test pads only |
| **Total** | **19-20** | about 1-2 spare. VBUS sense goes on the last ADC1 pin if one remains. |

Strapping pins GPIO8, GPIO9 and GPIO15 keep their boot defaults: GPIO8 high, GPIO9 button pull-up. The schematic (`.3.3`) assigns pins.

## Consequences

- **Thermal:** the module is rated to 85C, the same limit as the probe ADC. The ICD's thermal requirement covers both.
- **Firmware target:** `riscv32imac-unknown-none-elf` with esp-hal, esp-wifi and embassy-executor. The host digital twin runs the same `minimeat-core` on std.
